# 仕様書: Clipy機能ギャップ分析と実装プラン

作成日: 2026-07-25

## 1. 比較対象

- Clipy: https://github.com/Clipy/Clipy （公式サイト https://clipy-app.com）
- rekie-sekie: 本プロジェクト（2026-07-25時点の実装）

Clipyのソースコードは非公開機能も多く、READMEには詳細な機能一覧が無いため、
公式サイトの説明とユーザーブログ記事（Qiita・各種解説サイト）から機能を推測している部分がある。

## 3. 実装プラン（優先度順フェーズ）

### フェーズ1: 実用上の欠落機能（実装済み・2026-07-25）
1. 履歴最大件数のUI設定化 — 設定ウィンドウに件数入力を追加し`UserDefaults`に保存、`ClipboardMonitor`の`maxItems`に反映
2. ログイン時起動 — `SMAppService.mainApp.register()`（macOS 13+）を設定ウィンドウのトグルから制御
3. 除外アプリ設定 — コピー時の最前面アプリ（bundle identifier）を判定し、除外リストに含まれる場合は履歴に残さない。設定ウィンドウにアプリ選択UIを追加

### フェーズ2: セキュリティ関連（実装済み・2026-07-25、保留中TODOの解消）
4. `org.nspasteboard.ConcealedType`のチェック — パスワードマネージャー等が付与するマーカーを検知したコピーは履歴に残さない（README記載のTODOを解消）。設定でON/OFF切り替え可能

### フェーズ3: 画像対応（実装済み・2026-07-25）
5. クリップボード履歴の画像対応 — `Data`（TIFF）としてDBへ保存し、一覧にサムネイル表示

### フェーズ4: スニペット機能（実装済み・2026-07-25）
6. スニペット（定型文）の追加・編集・削除 — 右クリックメニュー「スニペット管理...」から
7. フォルダ分け管理 — フォルダの追加・削除、フォルダ単位でのスニペット分類
8. スニペット専用のショートカット/メニュー — ⌃⇧⌘V（設定で変更可）で専用ポップオーバーを開き、
   番号(1-9)・矢印キー+Enter・クリックでクリップボード履歴と同じ操作性を持たせた
9. スニペットの動的変数 — `{date}`(yyyy-MM-dd) `{time}`(HH:mm:ss) `{datetime}`(yyyy-MM-dd HH:mm:ss) を
   貼り付け時点の日時に展開する

### フェーズ5: UI/UX強化（実装済み・2026-07-26）
10. 履歴の検索・フィルタ（インクリメンタルサーチ） — 実装済み。検索欄フォーカス中は数字キーをクイック選択に使わないよう分岐
11. メニューバーアイコンのカスタマイズ — 実装済み。設定画面でSF Symbolの候補から選択
12. 環境設定ウィンドウのタブ化（実装済み・2026-07-25、一般/履歴/プライバシーの3タブ。スニペット実装時に専用タブを追加）

### フェーズ6: 配布・運用（実装済み・2026-07-26）
13. Sparkleによる自動アップデート（実装済み・2026-07-26、SPM経由でSparkle 2.9.4を追加。`generate_keys`でEdDSA鍵ペアを生成し
    秘密鍵はGitHub Secrets（`SPARKLE_PRIVATE_KEY`）、公開鍵は`Packaging/Info.plist`の`SUPublicEDKey`に埋め込み。
    appcastは`docs/appcast.xml`をraw.githubusercontent.com経由で配信し、`release-build.yml`が
    リリースのたびに`generate_appcast`で署名付きエントリを追記してmasterへコミット。
    メニューバーの右クリックメニューに「アップデートを確認...」を追加）
14. notarize・配布パッケージ化（実装済み・2026-07-25、Apple Developer Program登録・Developer ID Application証明書発行・
    App Store Connect API key発行が完了し、`.github/workflows/release-build.yml`でGitHub Release作成時に
    ビルド→codesign（Hardened Runtime、Sparkle.frameworkの内包コードも個別署名）→notarize→staple→zip添付まで自動化。
    ローカルで`spctl --assess`によるGatekeeper通過（`accepted, source=Notarized Developer ID`）まで実地検証済み）

## 4. 備考

- 「コピー内容が既存履歴と一致する場合は新規追加せず先頭に移動」はrekie-sekie独自の改善点。
  一般的なクリップボードマネージャーは重複を許容し新規行を追加する実装が多いと見られる。
- 各フェーズは独立して着手可能。フェーズ1・2は既存コードへの追加が中心で影響範囲が小さく、
  フェーズ3以降はデータモデル（`ClipItem`）の拡張を伴うため設計変更のコストが上がる。
